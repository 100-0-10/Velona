# 초기 개발 환경과 구조

## 저장소와 이름

공식 저장소는 `100-0-10/Velona`입니다. 이전 기획 폴더 이름 Velora와 다르며 기존 기획의 가칭은 원본에 남겨 두었습니다. 실행 프로젝트와 화면에서는 Velona를 사용합니다.

프론트와 백엔드는 독립 프로젝트이고 하나의 저장소에서 변경·검사합니다. 기획용 JSON은 docs/design/data에 보관합니다. 초기 서버는 그중 items·recipes·stations를 배포물 Content/Design으로 복사해서 사용하므로 publish 후 원래 저장소 위치에 의존하지 않습니다.

## 도구 선택

서버 솔루션 `backend/Velona.slnx`는 Visual Studio 2026에서 엽니다. VS Code에서는 저장소 전체를 열고 frontend와 docs를 함께 수정합니다. 도구 추천은 `.vscode/extensions.json`에 있습니다. 서로 다른 IDE에서도 같은 실제 파일을 사용합니다.

Node 24와 .NET 10 SDK를 사용합니다. npm 의존성은 frontend/package-lock.json으로 고정합니다. .NET SDK는 global.json에서 10.0 계열의 설치된 안정 버전을 허용합니다. 이 프로젝트는 Unity 런타임을 요구하지 않습니다.

## 서버 책임

클라이언트는 이동 의도와 행동 요청만 보내며 서버가 위치·사거리·재료·전투·해체 권리·작업 결과를 확정합니다. 이동은 20Hz, 상태 전달은 10Hz부터 검증합니다. 순간 좌표를 신뢰하지 않고 방향을 정규화합니다. 오래된 입력은 중단합니다.

게스트 토큰은 개발 세션용입니다. 토큰이 없는 연결과 다른 사용자의 상태를 바꾸는 요청은 거부합니다. 요청 id 재시도는 자원을 중복 차감하거나 보상을 다시 지급하지 않아야 합니다. 게스트 만료는 30일이고 PostgreSQL에 토큰 해시를 저장합니다. 정식 회원 인증과 복구 수단은 다음 작업입니다.

정식 서비스가 준비되기 전 이 개발 서버를 공용 운영 서비스로 배포하지 않습니다. Production 환경에서 게스트 접근은 기본 비활성입니다. 로컬 HTTP 주소는 개발 전용이며 운영 연결은 HTTPS·WSS·명시한 원본·정식 인증을 사용해야 합니다.

## 실제 구현과 기획의 차이

| 항목 | 현재 시제품 | 전체 기획 |
| --- | --- | --- |
| 공간 | 야영지와 작은 초원 1개 | 기후별 10종 지역·개인 거점 |
| 생물 | 멧수 1종 | 30종 기획 |
| 장비 | 제공되는 창·칼과 가방 제작 | 장비 93종 기획 |
| 제작 | 섬유끈·수피 분말·가죽 전처리·무두질·건조·가방 | 277개 제작법 |
| 생산 속도 | 개발 기본 0.05배 | 원래 설계 시간 기준 조정 |
| 생산 수령 | 완료 후 1회 자동 지급 | 설비별 수동 수령·연속 예약 |
| 설비 | 초기 야영지 제공·거리 검사 | 직접 건설·개인 권한·개선 |
| 물·도구 | 야영지 공급·초급 도구 제공 | 물 저장·연료·내구도 |
| 저장 | PostgreSQL 1초 체크포인트·재시작 복구 | 아이템별 거래 장부·백업·마이그레이션 |
| 인원 | 30명 입장 상한 | 30명 밀집 부하 통과 후 서비스 |

이 차이는 시제품 범위를 제한하기 위한 것입니다. 원본 기획 데이터를 짧은 시제품 시간에 맞춰 덮어쓰지 않습니다.

## 자동 검사와 배포 경계

CI는 읽기 권한으로 실행하며 비밀키가 없어도 데이터·빌드·검사를 수행합니다. 운영 서버와 DB를 변경하는 배포 작업은 아직 없습니다. 웹 빌드와 서버 publish 결과는 Actions 산출물에서 받을 수 있습니다.

PostgreSQL 저장은 별도 작업에서 1초마다 수행하며 재시작에 작업·인벤토리·해체 권리를 복구합니다. 갑작스러운 종료 직전 약 1초는 손실될 수 있습니다.

테스트용 서버는 localhost에 바인딩합니다. 브라우저 통합 검사는 별도 게스트 두 명의 연결·이동·생산과 화면 상태를 확인합니다. 소프트웨어 WebGL의 테스트 프레임은 실제 GPU 성능으로 해석하지 않습니다.
