## 실제로 플레이한 흐름

새 게스트가 야영지에 입장하고 동쪽으로 걸어가 멧수를 공격·처치했다. 개인 해체에서 외피를 선택하고 생가죽을 받았다. 섬유와 수피를 직접 채집하고 야영지로 돌아와 섬유끈4개·수피 분말6개·손질 가죽3개·무두질3회·건조3회 후 작은 가죽 가방을 만들었다. 재료가 차감되고 가방이1개 남았으며 새로고침 후 유지됐다.

이동은 실제 키보드, 제작은 실제 버튼으로 실행했다. 검사 전용 자원 지급·순간이동·서버 상태 조작 기능은 넣지 않았다. 두 번째 브라우저에서 같은 플레이어 이동을 관찰하고 채팅 입력 중 이동 키가 작동하지 않는지도 확인했다.

수정한 검사 동선 문제: 이전 경유점의 도착 오차 때문에 수피가 채집 범위를 벗어났다. 섬유와 수피 지점에 각각 접근하도록 수정한 후 전체 검사가 통과했다. 게임의 채집 거리 조건을 검사 편의로 늘리지는 않았다.

## PostgreSQL 검증

로컬127.0.0.1:7738의 velona_dev DB에 velona_admin 계정을 사용한다. 관리자 계정은 최초 생성 때만 사용했고 앱은 전용 계정으로 접속한다. 비밀번호는 저장소에 없다.

검증 스크립트는 일반 월드와 다른 키의 시험 월드를5151에서 실행한다. 채집 후 생산을 시작하고 재료 차감·실행 중 작업이 저장된 것을 확인한 뒤 강제 종료한다. 완료 시각 이후 다시 시작하면 결과가1회 지급되고, 같은 요청을 다시 보내도 중복 소비·지급되지 않는다. 완료 결과 저장 후 두 번째 재시작에도 수량이 유지됐다.

## 화면과 자산

1440×900과390×844 화면에서 확인했다. 캔버스 크기·색상 다양성과 밝기 범위도 검사해 빈 화면을 배제했다. PC 중심의 조작 검증이며 모바일은 배치와 화면 표시 확인 수준이다. 브라우저 자동 검사의 소프트웨어 렌더링 속도를 실제 GPU 프레임으로 주장하지 않는다.

현재 모델은 직접 구성한 시제품 캐릭터·멧수·나무·돌·야영지·제작 설비다. 외부 생성 모델·음향·최종 텍스처는 아직 없다. 웹 UI와 생산 진행은 서버 상태에 연결했다. 개발용 내부 관찰 정보는 개발 환경에서만 제공하고 배포 빌드에는 기본적으로 없다.

스크린샷 기반 회귀 기준선은 장면과 자산이 확정되기 전이므로 아직 고정하지 않았다. 실제 입력·상태·캔버스 검사와 화면 증거를 우선 사용한다. 물리는 단순한 서버 원형 충돌·월드 경계이며 강체 엔진은 사용하지 않는다.

## GitHub 자동 검사

main·PR·수동 실행에 데이터·프론트·서버·브라우저 검사를 구성했다. 브라우저 작업은 독립 PostgreSQL18 컨테이너와 임시 CI 인증을 사용하며 이 PC의 계정·DB에는 연결하지 않는다. Actions 실행 결과는 저장소 Actions 화면에서 확인한다. 자동 운영 배포는 없다.
