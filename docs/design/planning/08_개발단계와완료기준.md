# 개발 단계와 완료 기준

## 현재 완료한 단계

기획 기준선·지역·몬스터·원재료·생활 공정·장비·특성·데이터 연결·기술 선택·개발 순서를 문서화했다. 런타임·모델·네트워크·DB·빌드·플레이 검증은 아직 시작하지 않았다.

## 개발 단계

| 단계 | 구현 내용 | 통과 조건 |
| --- | --- | --- |
| P0 설계 검토 | 현재 기획·데이터·우선순위 | 선행 재료·장비 특성·출시 범위 검토 |
| P1 연결과 이동 | PC 화면·맵 1개·C# 서버·2인 이동 | 위치 보정·충돌·재접속·입력 세션 1개 |
| P2 사냥과 권리 | 돌창·생물 1종·개인 해체 | 예고→회피→처치→집중 선택→개인 보상 |
| P3 생활 연결 | 전처리·무두질·건조·가방 | 재료 투입·오프라인 완료·중복 수령 차단 |
| P4 개인 거점 | 집·창고·시설·방문 | 배치 충돌·권한·작업 중 철거·복구 |
| P5 생활 알파 | 초원·숲·습지·농사·도기·약재 | 방수·보존·제작 선택이 탐험을 바꿈 |
| P6 온라인 검증 | 채널·4인 보스·10/20/30명 | 밀집·단절·인원 이동·이중 보상 없음 |
| P7 운영 테스트 | 시장·화폐·관리·신고·백업 | 동시 구매·복구·감사·재화 장부 일치 |
| P8 콘텐츠 확장 | 협곡·냉대림·우림 | 금속·직조·훈연의 공급·소비가 이어짐 |
| P9 상위 콘텐츠 | 설산·화산·유적·1~8인 원정 | 솔로 경로·인원 배율·특성 조합 검증 |

## 반드시 실제로 확인할 시나리오

1. 신규 계정이 필수 재료를 잘못 써도 튜토리얼을 끝낸다.
2. 숲에서 얻은 생가죽으로 가방을 만들고 실제 운반 칸이 늘어난다.
3. 종료 전에 건 무두질이 재접속 후 완료되며 여러 번 수령되지 않는다.
4. 두 명이 같은 생물을 잡고 각자 하나의 집중 부위를 선택한다.
5. 방수·방한 장비가 환경 부담을 줄이지만 동급 공격 장비를 모두 대체하지 않는다.
6. 같은 상품을 동시에 구매해도 한 사람에게만 소유가 이전된다.
7. 채널 이동·거래·염색·개조로 신선도·내구·보상 권리가 초기화되지 않는다.
8. 친구는 부여받은 범위의 시설만 사용하고 창고·철거를 임의로 실행하지 못한다.
9. 30명이 좁은 지점에서 사냥·가공·채팅할 때 서버 틱·브라우저 프레임·전송량을 측정한다.
10. 서버 재시작과 DB 복구 후 생산·거래·재화가 일치한다.

## 최초 성능 측정 목표

서버 20Hz에서 p95 틱 처리 25ms 이하·지속적인 50ms 초과 없음부터 시험한다. 정해진 시험 기기·브라우저에서 일반 PC 장면 평균 60fps·p95 프레임 25ms 이하를 목표로 삼는다. 150ms RTT·일부 단절을 주입해도 이중 처리나 큰 위치 오류가 없어야 한다. 목표를 지키지 못하면 AI 수·관심영역·자산·전송을 측정해 조정하고 정원 50명 확대를 보류한다.

## 자산 준비 순서

캐릭터 체형 1종·창·가죽 장비·작은 초식수·멧수·갑각수의 실루엣을 먼저 맞춘다. 초원·숲의 바위·나무·지면·작업대·무두질·건조대·상자를 공통 모듈로 만든다. 후속 생물은 같은 체형·리그를 재사용할 수 있는지 확인하되 색만 바꿔 별종으로 취급하지 않는다. 발광은 유적의 일부 기관·연결부에 한정한다.

상세 모델·텍스처·사운드·아이콘은 아직 없다. 제작 단계에서 외부 자산·생성 도구·수작업을 비교하고 사용권·다각형·재질·리깅·웹 용량을 확인한다. 현재 외부 자산 생성이나 자격증명 확인은 필요하지 않은 설계 단계다.

## 개발 시작 전에 우선 정할 항목

첫 화면의 이동·카메라·장비 실루엣, 솔로와 협동 사냥의 체감, 한 번 접속하는 평균 길이, 신선도 부담, 재료 변형으로 늘어나는 창고 양, PC 최소 기기부터 먼저 확인한다. 비용과 기간은 P1~P3 실측 후 산정한다.
